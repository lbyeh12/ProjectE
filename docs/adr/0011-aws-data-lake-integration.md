# ADR 0011: AWS 클라우드 데이터 레이크 연동

## Status

Accepted

## Context

지금까지의 모든 데이터는 로컬 PostgreSQL 안에만 존재한다.
클라우드 환경에서 데이터를 수집·정제·적재한 실무 경험이 전혀
없다는 게 이 프로젝트의 가장 큰 공백이다. 데이터 엔지니어 직무는
대부분 클라우드 데이터 플랫폼(S3/Glue/Athena, Databricks,
Snowflake 등) 사용을 전제로 한다.

## Decision Drivers

- 실제 클라우드 계정으로, 시뮬레이션이 아닌 진짜 경험을 만들어야 함.
- 비용이 거의 들지 않아야 함(개인 프로젝트, 무료 티어 한도 안).
- 기존 배치 인프라(Airflow)를 재사용해야 함.

## Considered Options

1. **AWS (S3 + Glue + Athena)** — 채용 공고에 Glue가 명시적으로
   언급됨. S3/Athena는 프리 티어로 충분히 검증 가능한 규모.
   생태계 문서/커뮤니티가 가장 크다.
2. **MinIO(자체 호스팅 S3 호환 스토리지)** — 비용이 전혀 없고
   로컬에서 바로 검증 가능하지만, "클라우드 실무 경험"이라는
   목적 자체를 충족하지 못한다(진짜 클라우드 계정이 아님).
3. **GCP(BigQuery) / Azure(Synapse)** — 동등하게 유효한 선택이나,
   채용 공고가 AWS Glue를 구체적으로 예시로 들어 AWS를 우선한다.

## Decision

**AWS(S3 + Glue + Athena)를 채택한다.** MinIO는 비용 없이 검증만
가능할 뿐 실제 클라우드 경험이 되지 않아 이번 목적에 맞지 않다고
판단해 제외했다.

```
PostgreSQL(raw_events, fact_events)
    │  (Airflow 배치 태스크로 추출)
    ▼
S3 (Parquet, 날짜별 파티션)
    │
    ▼
Glue Crawler (스키마 자동 인식 → 카탈로그)
    │
    ▼
Athena (SQL로 조회)
```

- 새 컴포넌트(별도 ETL 도구) 없이 Airflow DAG에 "S3로 내보내기"
  태스크를 추가하는 방식으로 구현한다.
- 비용 관리를 위해 프리 티어 한도 안에서만 동작하도록 데이터
  양을 제한하고, 사용 후 리소스를 정리(bucket 삭제 등)한다.

## Consequences

- **좋아지는 점**: 실제 AWS 계정을 통한 클라우드 데이터 수집·적재
  경험을 확보한다. 채용 공고의 핵심 요구사항(클라우드 환경 실무
  경험)에 직접 대응한다.
- **감수해야 하는 점**: AWS 자격 증명 관리, 프리 티어 한도 초과
  방지를 위한 모니터링이 추가로 필요하다. 로컬 전용이던 프로젝트가
  외부 계정에 의존하게 되어, 재현(다른 사람이 그대로 실행)이
  더 어려워진다.
- **후속 작업**: 비용 알림(Billing Alarm) 설정. README에 AWS
  자격 증명 없이도 프로젝트의 나머지 부분은 동작한다는 점을 명시.
